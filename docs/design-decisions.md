# Design decisions and known limitations

本文记录 ReproPilot 的关键工程取舍。目标不是把原型描述成生产平台，而是解释当前设计解决了什么、放弃了什么，以及下一阶段需要怎样演进。

## 1. 显式 DAG，而不是自由对话推进

**选择**：Planner 输出带依赖、输入/输出 Artifact、工具权限、预算和重试策略的 `PlanGraph`。

**原因**：论文复现和仓库实验是长任务。依赖隐式对话历史推进时，无法可靠回答哪个节点可运行、失败影响哪些下游、服务重启后从哪里继续，也难以限制不同 Agent 的权限。

**代价**：新增任务类型需要定义节点和 Artifact 契约；固定模板的灵活性低于完全自由的 LLM Planner。

**边界**：当前意图分类以确定性规则为主，适合作为可解释 fallback，但不是已经上线的学习型路由系统。

## 2. 专业 Agent 分工，但不把角色数量当成能力

**选择**：Librarian、Coder、Research Coding、Sandbox 和 Data Agent 按工具与 Artifact 边界分工，Scheduler 负责协作。

**原因**：文献理解、仓库写入、代码执行和指标判定的权限风险不同。将它们放进一个全能 Agent 会扩大提示词、工具和故障面。

**代价**：角色间需要更多结构化数据转换；过细拆分会增加延迟和调试成本。

**边界**：这些角色共享同一单机运行时，不代表分布式 Agent 集群。多 Agent 的价值来自契约、调度与故障隔离，而不是角色名称。

## 3. 模型提出候选，确定性 Harness 掌握写入和验收

**选择**：模型输出诊断、假设和完整文件候选；路径检查、写入、命令执行、指标提取、Keep/Reject 与回滚由 Python 代码完成。

**原因**：模型既修改代码又解释结果时，容易出现越界写入、自报指标和失败合理化。将决策权移到冻结契约，可以审计每次修改为何被接受。

**代价**：每类任务都需要明确 evaluator，开放式研究问题不能直接套用同一指标。

**边界**：通过任务 evaluator 只证明该契约满足，不等于完整论文结论或通用代码质量得到证明。

## 4. 重复测量与隐藏验收，而不是一次公开分数

**选择**：baseline 与候选支持 1–5 次重复测量和 `mean`、`median`、方向相关 `worst` 聚合；最终可使用候选模型不可见 holdout。

**原因**：单次执行可能受随机性或瞬时状态影响；持续针对公开 evaluator 优化也可能过拟合。

**代价**：命令次数和模型反馈周期增加。隐藏测试还需要维护独立契约。

**边界**：重复新进程不自动等同于不同随机种子。当前 holdout 通过上下文隐藏、文件保护和哈希保证边界，不是独立零信任评测服务。

## 5. 线性受限搜索，而不是宣称完整树搜索

**选择**：AutoResearch 使用有预算的线性候选循环；ToT 只用于论文消融候选的两阶段生成、评分与预算剪枝。

**原因**：线性 Trial Ledger 更容易审计、回滚和复现，也与当前单机预算相匹配。

**代价**：失败知识主要通过文本反馈传递，没有并行 worktree、父子 lineage 或 checkpoint 分支恢复。

**边界**：项目不能表述为已经实现 Arbor、AI Scientist v2 或通用多分支研究树。

## 6. 原子 JSON 单节点存储，而不是提前引入分布式数据库

**选择**：`FilePlanStore` 通过临时文件、`fsync` 和原子替换保存计划与事件；启动时清理中断节点租约并恢复调度。

**原因**：当前目标是可恢复的个人研究工作流。该方案部署简单，也能验证状态机和恢复语义。

**代价**：写入吞吐、查询能力和多副本一致性有限。

**演进**：多副本部署需要事务数据库、分布式 lease 或 leader election，并保留现有 execution epoch 语义。

## 7. 独立 Sandbox Service，但承认 Docker Socket 风险

**选择**：Backend 通过 Bearer Token 调用独立 Sandbox Service；后者使用 Docker SDK 创建受限任务容器。

**原因**：把容器生命周期和安全校验从 Agent 逻辑中分离，便于测试和替换执行引擎。

**代价**：Sandbox Service 当前可以访问 Docker Socket，服务被攻破时宿主风险仍然较高。

**演进**：公网不可信租户应使用独立 Worker、rootless runtime、gVisor/Kata 或云端短生命周期沙箱，并加入可信身份、Secret 管理和审计。

## 8. 当前产品边界

- 单节点研究执行原型，不是生产级分布式调度平台；
- Header/Cookie 身份适合本地工作流，不是公网多租户认证；
- 没有可对外声称的并发规模、SLA、用户量或论文复现成功率；
- 外部仓库、私有数据集、Checkpoint 和 GPU 运行仍受依赖、资源与授权条件限制；
- 浏览器验证与 CI 不能替代跨浏览器、移动端、无障碍和生产安全评估。
