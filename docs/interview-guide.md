# 项目说明与常见问题

## 项目定位

ReproPilot 是一个面向论文与代码实验的多 Agent 执行系统。它将研究任务拆成多个步骤，让不同 Agent 分别处理文献、代码、执行和数据工作，并由系统统一验证结果。

## 四个主要能力

- **多 Agent 任务编排**：将复杂任务拆成带依赖关系的步骤，并支持失败重试、取消和任务恢复。
- **受控代码实验**：模型提出代码候选，系统限制修改范围、执行统一评测并决定保留或回滚。
- **结果验证与记录**：系统重新运行评测并保存实验过程，避免只依赖模型给出的结果描述。
- **Docker 隔离执行**：在独立容器中运行代码，并限制资源、网络、时间和输出大小。

## 简短介绍

ReproPilot 不是普通聊天应用，而是把研究任务继续推进到代码执行和结果验证。多个 Agent 按步骤分工，模型可以提出修改方案，但是否保留修改由系统运行评测后决定。代码在 Docker 中执行，实验过程和结果会被保存，便于后续检查。

## 常见问题

### 为什么需要多个 Agent？

文献理解、代码修改、程序执行和数据验证需要不同的上下文与工具。拆分后每个 Agent 只处理自己负责的步骤，流程更清楚，也更容易定位问题。

### 怎样避免模型自己宣布成功？

模型只提出候选修改。系统会使用预先确定的评测方式重新运行代码，并根据实际结果决定保留还是回滚。

### Docker 是否代表代码绝对安全？

不是。Docker 主要用于隔离依赖和限制资源，可以降低运行外部代码的风险，但当前实现只适合本地与受控环境。

### 测试是否已经完善？

后端核心流程和 Docker 执行已有自动化测试与 CI，前端目前主要依赖类型检查、构建和人工验证。后续会补充前端组件测试、覆盖率基线和浏览器端到端测试。

## 表述边界

- 不描述为生产级分布式平台；
- 不声称能够完整复现任意论文；
- 不使用当前仓库无法证明的性能提升、用户规模或成功率；
- 通过既定评测只代表当前任务要求被满足。
